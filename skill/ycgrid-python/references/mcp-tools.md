# YCGrid MCP tool reference

> Generated by `mcp/gen_tools_doc.py` from `mcp/tools.json`; do not edit by hand.

## Ground rules

- Getting started: `yc_connect` -> `yc_get_workbook_info`; the project entry point is `main.py`.
- Before writing code: confirm the API really exists with `yc_api_lookup`.
- After changing `.py` files: `yc_reload_python` -> `yc_python_status` (check the registrations) -> test -> `yc_read_console`.
- How to test:
  - macros: `yc_run_macro`.
  - buttons and combo boxes: `yc_trigger_control`.
  - per-cell OnChange: write the target cell with `yc_write_range`, or use `yc_ui_input`.
  - sheet events (Change, SelectionChange, double-click, shortcuts): `yc_ui_input`.
  - UDFs and formulas: `yc_evaluate_formula`.
  - market data events and formulas: push with `yc_topics`.
- Checking results: values with `yc_read_range`; styles and the dependency tree with `yc_inspect_cells`; the look with `yc_screenshot` (scroll there first with `yc_scroll_view` if needed).
- Operations without a dedicated tool (conditional formatting, data validation, defined names...): use the object model through `yc_exec_python`, or run a UI command with `yc_execute_command`.
- Missing Python packages: `yc_install_packages` (installed into the project's own runtime, the system Python is not touched).
- Tools marked "runs user code" may trigger real trades: without the user's consent, never use them on macros, controls or events related to placing orders or changing positions.

## Common output

- The first line is the conclusion; large results are truncated with a hint on how to get the next page.
- Results are text (JSON for structured results; `yc_screenshot` returns an image).
- On failure `isError=true` and the text says what went wrong and what to do: `Invalid arguments: ...` for a wrong
  parameter, a tool's own message (an unknown sheet lists the sheets; `confirm=true` / `discard_changes=true` when an
  action needs them), `YCGrid reported an error: ...` for an error from YCGrid (its message; `yc.YcError.Code` in
  Python: `E_ARG`, `E_NOT_FOUND`, `E_APP`, `E_FORMULA`, `E_PROTECTED`, `E_PASSWORD`, `E_UNSUPPORTED` (not implemented
  yet), `E_TIMEOUT`...), or `The connection to YCGrid was lost` (start YCGrid, then `yc_connect`).

## Tools

### `yc_connect` — Connect to YCGrid

Nature: read-only | Milestone: M6

Lists the YCGrid instances running on this machine and selects the one the other yc_* tools work on. Without target: selects automatically when the current workspace (program folder) has a matching instance or there is only one instance; otherwise returns the candidates, so call again with target. Other tools apply the same rule automatically when not connected yet. Returns: the instance list (instance_id, pid, program folder, workbook, Python host state, protocol version) and the selected instance.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `target` | string |  |  | Instance to select: instance_id, pid or program folder path. |

### `yc_get_workbook_info` — Workbook overview

Nature: read-only | Milestone: M6

Gets the overall state of the current workbook; usually the first tool to call. Includes: the file path and whether there are unsaved changes; for every sheet its name, CodeName, index, visibility, used range, number of controls and charts, and whether its Python sheet module file (e.g. sheets/Sheet1.py) exists; defined names; the active sheet and selection; the calculation mode and the last recalculation statistics; Design Mode; a summary of the Python host state. ### `yc_read_range` — Read range contents

Nature: read-only | Milestone: M6

Reads the values, formulas, displayed text or number formats of a range as a table with row numbers and column names. Values: numbers as is, text quoted, blanks empty, errors such as #N/A, dates according to date_mode. Ranges larger than max_cells are truncated with a hint about the row_offset of the next page; use summary_only to just learn the shape of the data. For styles, dependencies and other details use yc_inspect_cells.

| `sheet` | string |  |  | Sheet name, CodeName or 1-based index; the active sheet when omitted. Ignored when address already has a sheet prefix. |
| `fields` | array of string |  | ["value"] | What to read; several may be chosen. Only values by default.One of: `value`, `formula`, `text`, `number_format`. |
| `max_cells` | integer (1-20000) |  | 2000 | Maximum number of cells to return. |
| `row_offset` | integer (0-) |  | 0 | Paging: the row within the range to start from (0-based). |
| `date_mode` | string |  | "iso" | How dates are shown: iso = 2026-10-11T09:00:00; serial = Excel serial number.One of: `iso`, `serial`. |
| `summary_only` | boolean |  | false | Only return the shape (rows, columns), the first row and each column's kind (number, text or empty). |

### `yc_write_range` — Write values or formulas

Nature: modifies the workbook or state, may overwrite or delete, runs user code | Milestone: M6

Writes values or formulas into a range, like Range.Value / Range.Formula. Pass a 2D array in values (outer = rows, inner = columns, its size must match address), or fill the whole range with one value via fill_value; use one of the two. With mode=auto, strings starting with "=" are formulas; relative references in formulas are adjusted by Excel's rules ("=B2*C2" written to D2:D100 adjusts row by row). It fires Worksheet_Change like a user edit. Like every Python write it is not recorded in the user's undo list and doesn't clear it (ADR 0013): the user can't take it back with Ctrl+Z, and the user's own earlier steps stay. Returns the number of cells written and the shown text of the first rows.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `address` | string | ✓ |  | A1 address, may include a sheet prefix or be a defined name, e.g. "B2:K100", "Quotes!A1", "'My Sheet'!A1:C3", "QuoteArea". |
| `sheet` | string |  |  | Sheet name, CodeName or 1-based index; the active sheet when omitted. Ignored when address already has a sheet prefix. |
| `values` | array of array of string / number / boolean / null |  |  | 2D array, outer = rows, inner = columns; every cell may be a string, number, boolean or null (clears the cell). |
| `fill_value` | string / number / boolean / null |  |  | A single value that fills the whole range (use either this or values). |
| `mode` | string |  | "auto" | auto = strings starting with = are formulas; values = always values (text starting with = included); formulas = always formulas.One of: `auto`, `values`, `formulas`. |
| `fire_events` | boolean |  | true | Whether to fire events such as Worksheet_Change. Not applied yet: false is only noted in the result; to fire no events, set Application.EnableEvents = False in the host (yc_exec_python target=host). |
| `undoable` | boolean |  | true | Not applied: Python's writes are never steps of the user's undo list (ADR 0013). |
| `wait_recalc` | boolean |  | true | Wait for the recalculation to finish before returning. |

### `yc_add_control` — Add a control

Nature: modifies the workbook or state | Milestone: M9

Adds an ActiveX-style control (button, combo box, check box, option button, toggle button, text box, label, list box, spin button, scroll bar or image) to a sheet, like drawing one in Design Mode on the Developer tab; controls can float anywhere. Position it with cover_range so it exactly covers a cell range (the most common way), or with left, top, width, height (in points). With placement=float_window it is fixed to the window and doesn't scroll. Events go in the sheet's module (sheets/<CodeName>.py): <Name>_Change for combo boxes, text boxes, spin buttons and scroll bars, <Name>_Click for the others (buttons, labels, images, check boxes, option and toggle buttons, list boxes); spin buttons also fire SpinUp / SpinDown, scroll bars Scroll. This tool never edits .py files; it only returns the control name, its actual position and suggested event function templates. It is not an undo step the user can take back: Python's writes are not recorded in the user's undo list (ADR 0013).

### `yc_reload_python` — Reload Python

Everything YCGrid shows, in one call and without a screenshot: whether the window is visible, the file, the open dialog (0 = none), the status bar text, operator mode, safety alarms, every sheet (name, used range, tables, charts), the active sheet, cell, selection and the active cell's value and formula, the bound tables (rows, recorded or not), the open yc.plot figures with their plots and items, the replay state and whether the Python host is ready. Use it to check the result of an action before taking a screenshot.

(no parameters)

### `yc_bound_tables` — Bound tables

Nature: read-only | Milestone: Roadmap 1

The live tables fed by key through shared memory (ws.bind / yc.data). list: each table's name, sheet, key column, declared columns and formats, freshness limit, whether it is recorded, and age (seconds since its newest row update; null before any data). read: a table's rows by column (numbers, text, dates as ISO text), read columnar through shared memory, up to max_rows.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `action` | string |  | "list" | The operation to perform.One of: `list`, `read`. |
| `table` | string |  |  | The table to read (any table, not only bound ones). |
| `max_rows` | integer (1-100000) |  | 200 | At most this many rows for read. |

### `yc_replay` — Record and replay

Nature: modifies the workbook or state | Milestone: Roadmap 4

Records the data reaching the bound tables to a .yctape file and replays it into the same tables (yc.replay; Trading > Record / Replay). While a replay runs, live data for its tables are ignored, so the screen and its Python code run on recorded data unchanged; live goes back to live data and restores the tables. Actions: status, record (path optional: the workbook's recordings folder; tables optional: the tables marked for recording), stop_recording, play (path, speed: 0 = as fast as possible, start seconds, loop), pause, resume, seek (seconds), speed, live. Returns the replay status: mode (live / replay / paused / ended), position, length, speed, frames, the recording.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `action` | string |  | "status" | The operation to perform.One of: `status`, `record`, `stop_recording`, `play`, `pause`, `resume`, `seek`, `speed`, `live`. |
| `path` | string |  |  | The .yctape file for record and play. |
| `tables` | array of string |  |  | The bound tables to record. |
| `speed` | number (0-) |  | 1 | Replay speed (play, speed); 0 = as fast as possible. |
| `start` | number (0-) |  | 0 | Seconds from the start of the recording (play). |
| `seconds` | number (0-) |  |  | The time to seek to. |
| `loop` | boolean |  | false | Replay again from the start at the end (play). |

### `yc_workbook_file` — Workbook file

Nature: modifies the workbook or state, may overwrite or delete, runs user code | Milestone: M13

Workbook file operations: save, save as (a single .ycg file, a copy as .xlsx, or the active sheet's values as .csv, which leaves the workbook's own file as it was), open (.ycg, .xlsx / .xlsm, .csv: Excel and CSV files open as a new, untitled workbook), new, export_pdf (a sheet or every visible sheet printed with its page setup). Saving is atomic, so a failure halfway never damages the original. Open and new replace the current workbook; with unsaved changes they only run with discard_changes=true. Fires Workbook_BeforeSave (a handler setting Cancel.Value = True stops the save) and Workbook_AfterSave for save / save_as, Workbook_BeforeClose and the new project's Workbook_Open for open / new.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `action` | string | ✓ |  | The operation to perform.One of: `save`, `save_as`, `open`, `new`, `export_pdf`. |
| `path` | string |  |  | File path (used by save_as, open and export_pdf). |
| `sheet` | string |  |  | export_pdf: the sheet to export (default: the active sheet). |
| `all_sheets` | boolean |  | false | export_pdf: export every visible sheet into one PDF. |
| `format` | string |  |  | Save As format; decided by the extension when omitted.One of: `ycg`, `csv`. |
| `discard_changes` | boolean |  | false | Discard the current unsaved changes when opening or creating a workbook. |

### `yc_api_lookup` — Look up the Python API

Nature: read-only | Milestone: M6

Looks up the documentation of the YCGrid Python object model (Excel compatible); YCGrid doesn't need to be running. Look up classes, members, constants, events, functions or Excel idioms, e.g. "Range.End", "Borders", "xlUp", "Worksheet_Change", "VLookup", "CommandButton", "UndoGroup". Returns the signature, parameters, description, the matching Excel idiom, whether it is a YCGrid extension [YC], the implementation status and examples. Use it to confirm a member really exists before writing code; don't invent APIs.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `query` | string | ✓ |  | Query string, such as a class name, Class.Member, a constant name, an event name or an Excel snippet. |
| `kind` | string |  | "any" | Restrict to a kind.One of: `any`, `class`, `member`, `constant`, `event`, `function`. |
| `max_results` | integer (1-50) |  | 10 | Maximum number of results. |

### `yc_extract_macros` — Extract Excel macro code

Nature: read-only | Milestone: M13

Extracts the macro project from an existing Excel file (.xlsm, .xlsb, .xls, .xlam): the code of standard modules, class modules, sheet modules (with CodeName), ThisWorkbook (maps to main.py) and UserForms, plus the controls on sheets: buttons (name, caption, position and OnAction macro of form and ActiveX buttons) and ActiveX combo boxes (name, position, ListFillRange, LinkedCell, Style) are listed in full so they can be rebuilt with yc_add_control; other controls only get name and type, to decide how to replace them. From an .xls file only the macro code is extracted, not the controls (save it as .xlsm in Excel to list them). This is the first step of porting old macros to YCGrid Python. YCGrid doesn't need to be running and no macro is ever executed. Only the macro code and the control list are read, not cell data; ask the user to copy the sheet contents in Excel and paste them into YCGrid.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `path` | string | ✓ |  | Path of the Excel file. |
| `include_controls` | boolean |  | true | Also list the controls on sheets. |
| `modules` | array of string |  |  | Only these modules; all when omitted. |
| `max_chars_per_module` | integer (1000-500000) |  | 50000 | Maximum characters returned per module; longer modules are truncated with a note. |
